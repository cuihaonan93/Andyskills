For a verified bundle, obtain an official 64-bit artifact or compile a clean pinned
release, record its source commit, compiler/options, architecture, and hash, and
confirm that the DLL rejects a missing or malformed `DISCON.IN`. Then verify a
valid turbine-specific input initializes and run a short OpenFAST smoke case before
using the bundle for data generation.

For another turbine, tune and write a new `DISCON.IN` using the selected ROSCO
release and that turbine's OpenFAST model/rotor performance. A common ROSCO release
does not imply common tuning parameters across turbines.

## Signal Map

For every exchanged value, record the `avrSWAP` record/index, semantic name, unit,
sign, reference frame, valid time, sampling period, filter/delay, initialization,
and whether it is a measurement, command, status, or configuration value.

At minimum, verify the enabled controller's required generator/rotor speed, blade
pitch, generator power/torque, time/status signals, nacelle/tower/platform feedback,
and command outputs. The exact set depends on `DISCON.IN` modes; never hard-code a
universal subset without checking those modes.

## Timing

Define this order explicitly for each sample:

1. Plant produces measurements at time `k`.
2. ROSCO consumes measurements and advances controller state.
3. Commands pass through configured filters, delays, and saturation.
4. Plant advances using the commands under the declared hold convention.

Match OpenFAST/ServoDyn behavior, controller sample time, status transitions, and
first/last-call semantics.

## Paired Comparison

Create independent controller instances for the OpenFAST and surrogate cases but
initialize them identically. Use the same environmental realization and termination
rules. Compare both controller outputs and plant responses; otherwise feedback may
hide interface or plant errors.
